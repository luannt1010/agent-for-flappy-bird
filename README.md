# Flappy Bird — Reinforcement Learning with PyTorch

A project for training and evaluating agents to play Flappy Bird from images using **Reinforcement Learning (RL)**. The game environment is built with Pygame, and the models are implemented using PyTorch.

You can play using the keyboard, watch trained AI agents play, compare multiple algorithms, and evaluate their adaptability when changing pipe speed, pipe gap, or wind conditions.

## Installation

Requires **Python 3.10 or later**. Run the following commands from the project root directory.

```bash
python -m venv .venv
```

Activate the virtual environment on Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

On Linux/macOS:

```bash
source .venv/bin/activate
```

Install the dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements-benchmark.txt
```

The main libraries include `torch`, `numpy`, `pygame`, `opencv-python`, `matplotlib`, and `tqdm`. The requirements file also includes `tzdata` on Windows for recording timestamps in the Vietnam time zone.

If you use an NVIDIA GPU, install a PyTorch version compatible with the CUDA version on your machine. Benchmarking supports `--device cpu`, `--device cuda`, `--device cuda:0`, and `--device auto` (automatically selects CUDA when available).

**The repository does not include pre-trained checkpoints.** You must train a model before running examples that require `best.pt`.

## Playing the Game

Play using the default environment or try a more challenging pipe configuration:

```bash
python game.py
python game.py --profile surprise
```

| Key | Action |
| --- | --- |
| Space / ↑ | Flap; start the game if waiting |
| Enter | Start or proceed to the next episode |
| P | Pause / resume |
| R | Replay the current pipe layout using the same seed |
| Esc | Exit |

The game window displays the score, session high score, total reward, and simulated survival time. The default speed is 30 FPS; use `--fps` to change the frame rate and `--scale` to adjust the window size. Completed episodes are summarized in the terminal; episodes that are restarted or exited before completion are excluded from these statistics.

### Let AI Play

Replace `duong-dan/toi/best.pt` with a **single-agent checkpoint generated by the benchmark**:

```bash
python game.py --profile surprise --checkpoint "duong-dan/toi/best.pt" --episodes 3
```

The algorithm and agent configuration are loaded from the checkpoint. The AI starts automatically, switches to the next seed after each episode, and only performs inference while playing. `--profile` selects the demonstration environment, which may differ from the environment used during training.

Run without opening a window and without an FPS limit:

```bash
python game.py --checkpoint "duong-dan/toi/best.pt" --headless --episodes 3
```

`game.py` uses CPU for inference by default; add `--device cuda` if needed. Session statistics are intended for observing agent behavior, while the benchmark workflow below provides evaluation across multiple seeds and environments.

## Algorithms and Environment

### Supported Algorithms

| `--methods` value | Description |
| --- | --- |
| `dqn` | Deep Q-Network baseline |
| `double_dqn` | Double DQN |
| `dueling_dqn` | DQN with a Dueling architecture |
| `per_dqn` | DQN with Prioritized Experience Replay |
| `rainbow` | Combines Double, Dueling, PER, n-step learning, NoisyNet, and C51 |
| `ppo` | Proximal Policy Optimization |
| `a2c` | Advantage Actor-Critic |
| `sac` | Soft Actor-Critic for discrete actions |
| `domain_randomization` | Compatibility name for DQN with environment randomization |
| `curriculum` | Compatibility name for DQN with a progressively increasing difficulty schedule |
| `multi_agent` | Independent DQN agents competing for survival on the same pipe layout |

Use `--methods all` to select all algorithms. For single-agent learners, you can independently select a training strategy using `--train-strategy fixed`, `domain_randomization`, or `curriculum`.

### Environment Profiles

| Profile | Changes compared to `standard` |
| --- | --- |
| `standard` | 100 px gap, pipe speed of −4 px/step, no wind |
| `narrow` | Reduces the pipe gap to 80 px |
| `fast` | Increases pipe speed to −6 px/step |
| `wind` | Adds downward wind with a coefficient of 0.35 |
| `combined` | Combines `narrow`, `fast`, and `wind` |
| `surprise` | Keeps standard physics; gap center positions range from 80–260 px, with an offset of 80–120 px between consecutive pipes |

Domain randomization samples new physics parameters at the beginning of each episode and requires `--train-profile standard`. Curriculum progressively increases the difficulty toward the target profile; `--curriculum-fraction` determines the portion of the training budget used to reach the target difficulty. `surprise` currently only supports the `fixed` strategy; `multi_agent` only supports `standard` / `fixed`.

### Observations, Actions, and Rewards

- **Observation:** A stack of 4 binary images, each with a resolution of 84 × 84, in `uint8` format, with shape `(4, 84, 84)`.
- **Action:** `0` allows the bird to fall according to the physics; `1` makes the bird flap upward.
- **Reward:** `+0.1` for each ordinary survival step, `+1` for passing a pipe, and `−1` for a collision.
- **Score:** The number of pipes passed, reported separately from the total reward.
- **Termination:** A collision results in `terminated`; reaching the maximum number of steps results in `truncated`.
- **Survival time:** `episode_steps / 30` simulated seconds, independent of actual execution speed.

## Training and Evaluation

### Training Multiple Algorithms

Example: Compare DQN, Double DQN, PER-DQN, and PPO on the standard environment using 5 training seeds:

```bash
python benchmark.py --methods dqn double_dqn per_dqn ppo --seeds 0 1 2 3 4 --train-profile standard --train-steps 1000000 --validation-interval 25000 --validation-episodes 10 --test-episodes 100 --eval-profiles standard narrow fast wind surprise combined --early-stopping-episodes 0 --device auto
```

Each algorithm/seed pair has a maximum budget of 1,000,000 transitions. By default, the benchmark runs without opening a window, displays progress using `tqdm`, and automatically evaluates the best checkpoint after training. Add `--no-progress` to disable the progress bar or `--output-dir` to change the output directory.

Examples of changing the training strategy:

```bash
python benchmark.py --methods double_dqn ppo --seeds 0 --train-profile standard --train-strategy domain_randomization --device auto
python benchmark.py --methods double_dqn ppo --seeds 0 --train-profile narrow --train-strategy curriculum --curriculum-fraction 0.8 --device auto
```

### Available Experiment Suites

| Configuration | Description | Default number of training runs |
| --- | --- | --- |
| [core.json](experiments/core.json) | DQN, Double DQN, PER-DQN, and PPO × 2 training profiles: `standard`, `narrow` | 40 |
| [full_matrix.json](experiments/full_matrix.json) | The same 4 algorithms × 5 training profiles: `standard`, `narrow`, `fast`, `wind`, `surprise` | 100 |
| [robustness.json](experiments/robustness.json) | Double DQN and PPO using domain randomization or curriculum toward `narrow` | 20 |
| [surprise.json](experiments/surprise.json) | Double DQN and PPO trained on `standard` or `surprise` | 20 |

The configurations use 5 training seeds and a budget of 1,000,000 transitions per run. `full_matrix.json` evaluates on all 6 profiles, including `combined`.

Preview the experiment plan and validate the configuration before running:

```bash
python benchmark_suite.py --config experiments/full_matrix.json --dry-run
```

Quickly test the training, evaluation, and report generation workflow on CPU:

```bash
python benchmark_suite.py --config experiments/core.json --smoke --device cpu
```

The `--smoke` mode uses 1 seed, 32 transitions per run, and a maximum of 40 steps per episode. These results only verify the execution workflow and do not reflect the agent's learning performance.

Run the complete experiment suite:

```bash
python benchmark_suite.py --config experiments/full_matrix.json --device auto
```

You can limit experiments and override the training budget when needed:

```bash
python benchmark_suite.py --config experiments/core.json --experiments fixed_standard --seeds 0 --train-steps 100000 --device cpu
```

### Re-evaluating Checkpoints

The `evaluate` mode does not perform training. Specify checkpoints using the `METHOD:SEED=PATH` syntax; the method and training seed must match the saved metadata:

```bash
python benchmark.py --mode evaluate --methods dqn --seeds 0 --checkpoint "dqn:0=duong-dan/toi/best.pt" --test-episodes 100 --eval-profiles standard narrow fast wind surprise combined --device cpu
```

If multiple methods or seeds are selected, repeat `--checkpoint` for each pair. Add `--render --render-fps 30` to watch evaluation episodes in the game window.

## Results and Checkpoints

A `benchmark.py` run generates the following directory structure:

```text
benchmark_results/<timestamp>/
├── results.json
├── summary.json
├── comparison_<profile>.png
├── comparison_<profile>.pdf
├── learning_curves.png
└── <method>/seed_<seed>/
    ├── best.pt
    ├── history.json
    └── train_summary.json
```

- `results.json`: Configuration, library versions, device information, SHA-256 fingerprints of the source code/assets, and results for each run.
- `summary.json`: Aggregated results by algorithm and profile, including score, reward, survival time, rates of reaching 10/50 pipes, and episode time-limit rates.
- `best.pt`: The checkpoint selected based on **average validation reward**, without using test results for model selection.
- `history.json`, `train_summary.json`: Validation history, update diagnostics, and training costs.
- Charts: Performance comparisons across profiles and validation reward learning curves.

Training, validation, and test use separate groups of seeds; validation starts from `1_000_000` by default, while testing starts from `2_000_000`. When aggregating multiple training seeds, the standard deviation is calculated across the mean values of individual seeds. Exact reproducibility may also depend on hardware, PyTorch version, and thread configuration.

Checkpoints are used for model selection and evaluation; the replay buffer and the complete state required to resume a training run exactly are not saved.

For `benchmark_suite.py`, results are stored by default in `benchmark_results/suites/<timestamp>/`. The `suite.json` file records the status of each experiment; the `comparison/` directory contains aggregated JSON files, charts, `comparison.csv`, `per_seed.csv`, and environment transfer tables: `transfer_score_mean.csv` and `transfer_score_std.csv`.

You can regenerate reports from an existing suite, including experiments that were completed in an interrupted suite:

```bash
python benchmark_suite.py --collect "benchmark_results/suites/thu-muc-suite"
```

This command only aggregates existing reports. The collector checks protocol compatibility, runtime compatibility, and source fingerprints, while also rejecting duplicate seed runs.
